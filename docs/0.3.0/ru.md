## 1. Подключить локально и подготовить PostgreSQL

Небольшой реактивный клиент с явным владением задачами. Для начала нужны Java 17+, PostgreSQL, артефакт библиотеки и одна миграция.

Руководство описывает локальную версию 0.3.0. Проверены Java 17, 21 и 25 LTS, а также Java 27. Публикация в Maven Central не настроена: сначала установите библиотеку из рабочей копии с версией 0.3.0.

```bash
cd pg-task-lease
./gradlew publishToMavenLocal -PtestJavaVersion=17
```

Результат: библиотека, POM, исходники и Javadoc установлены в локальный Maven-репозиторий. Команда ничего не публикует во внешний реестр.

```kotlin
repositories { mavenLocal(); mavenCentral() }
dependencies {
    implementation("io.github.59alex:pg-task-lease:0.3.0")
    runtimeOnly("org.postgresql:r2dbc-postgresql:1.1.3.RELEASE")
}
```

Зависимости приложения. Reactor Core и R2DBC SPI приходят с библиотекой; драйвер PostgreSQL выбирает приложение.

```bash
psql "$TASKS_PSQL_URL" -v ON_ERROR_STOP=1 -f schema.sql
```

Примените скачанный schema.sql один раз через ваш процесс миграций. Результат: таблица public.pg_task_lease и два индекса. Операций DROP в файле нет.

```java
import io.github.alex59.pgtasklease.*;
import io.r2dbc.spi.ConnectionFactories;
import java.time.Duration;
import java.util.UUID;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

var queue = new PgTaskQueue(
    ConnectionFactories.get(System.getenv("TASKS_R2DBC_URL")));
var wait = Duration.ofSeconds(10);
```

Разместите импорты перед объявлением класса, а инициализацию — в точке входа приложения или консольном методе main. TASKS_R2DBC_URL содержит параметры подключения; не храните рабочие учётные данные в коде.

> **Как читать примеры**
>
> Следующие фрагменты показывают отдельные операции и используют клиент queue из примера выше. Для операций с арендой нужен свежий действующий lease: фрагменты не следует исполнять подряд как один сценарий. Полный конечный сценарий есть в Example.java. Блокирующее ожидание используется только на границе консольной программы, а не внутри callback в event loop Reactor.

## 2. Создать задачу и безопасно повторить отправку

Выберите постоянный UUID до первой отправки. Повтор с тем же UUID не создаст ещё одну задачу.

```java
var taskId = UUID.randomUUID();
var request = new TaskRequest(taskId, "mail", "{"recipientId":42}",
    10, 3, Duration.ZERO);

boolean inserted = queue.submit(request).block(wait);
boolean duplicate = queue.submit(request).block(wait);
System.out.println(inserted + ", " + duplicate);
```

Для нового UUID результат: true, false. Второй вызов не заменяет содержимое, приоритет или лимит попыток.

- Поля TaskRequest: id, queue, payload, priority, maxAttempts, delay. Payload — непрозрачная строка, не равная null; библиотека не сериализует бизнес-объекты.
- UUID уникален для всех очередей сразу. Сохраняйте его в процессе отправителя: новый UUID при каждом сетевом повторе отменяет дедупликацию.
- Положительная delay откладывает доступность по часам базы. Чем больше priority, тем выше предпочтение; maxAttempts ограничивает число захватов, включая захваты перед падением работника.

> **Граница дедупликации**
>
> Дедупликация отправки действует, пока существует строка задачи. Она не устраняет повторы внешних действий обработчика. Удаление завершённой строки удаляет и запись о первоначальной отправке.

## 3. Забирать задачи несколькими работниками

Захват атомарно выбирает доступные строки и фиксирует владельца. Независимые работники могут обращаться к одной логической очереди.

```java
var queueName = "claim-demo-" + UUID.randomUUID();
Flux.range(0, 2)
    .concatMap(i -> queue.submit(new TaskRequest(UUID.randomUUID(),
        queueName, "{"kind":"demo"}", i, 2, Duration.ZERO)))
    .then().block(wait);

var leases = Flux.merge(
        queue.claim(queueName, "worker-a", 1, Duration.ofSeconds(30)),
        queue.claim(queueName, "worker-b", 1, Duration.ofSeconds(30)))
    .flatMapIterable(batch -> batch)
    .collectList().block(wait);
long distinctTasks = leases.stream().map(TaskLease::id).distinct().count();
System.out.println(leases.size() + ", " + distinctTasks);
```

С двумя готовыми задачами выше результат: 2, 2. Каждый захват возвращает неизменяемый список; пустой список означает, что доступных незаблокированных задач не найдено.

- Выбор использует PostgreSQL FOR UPDATE SKIP LOCKED. Заблокированную задачу с более высоким приоритетом можно обойти; глобальный FIFO завершений не гарантируется.
- Имена очередей разделяют выбор задач, но не права в базе. Для разных ролей приложения нужна собственная политика доступа к PostgreSQL.
- Размер захвата — от 1 до 1000. Задачи из партии должны начать обработку до истечения аренды: время ожидания внутри приложения тоже расходует её срок.

> **Подписка — это операция**
>
> Publisher в Reactor холодный. Повторная подписка на тот же publisher захвата выполняет новый захват, а не воспроизводит предыдущий список.

## 4. Завершать только с действующей арендой

TaskLease содержит токен и поколение. Вместе со сроком аренды в базе они защищают изменение состояния от старого работника.

```java
boolean acknowledged = queue.complete(lease).block(wait);
boolean repeated = queue.complete(lease).block(wait);
TaskSnapshot snapshot = queue.find(lease.id()).block(wait);
System.out.println(acknowledged + ", " + repeated + ", " + snapshot.state());
```

Для действующей непросроченной аренды: true, false, DONE. Старый, просроченный или уже завершённый lease вернёт false и не изменит строку повторно.

Вызывайте complete только после успешного результата обработчика. Клиент проверяет состояние, токен, поколение и время базы после получения блокировки строки. Диагностическая строка owner не является подтверждением владения.

> **Внешние действия остаются вне транзакции**
>
> Платёж, письмо или удалённая запись могут выполниться до падения процесса, который не успел подтвердить задачу. Следующая попытка может повторить действие. Используйте UUID задачи как ключ идемпотентности или транзакцию целевой системы; библиотека не обеспечивает exactly-once для внешних действий.

> **Потерянный ответ неоднозначен**
>
> Ошибка соединения после complete не доказывает откат: PostgreSQL мог зафиксировать изменение. При необходимости проверьте состояние. Сам по себе false при повторном complete не отличает ранее успешное подтверждение от потери владения.

## 5. Продлевать аренду долгой задачи

Heartbeat сохраняет текущее владение, когда обработке нужно больше времени. Запускайте его с запасом до истечения аренды.

```java
boolean renewed = queue.heartbeat(lease, Duration.ofSeconds(60)).block(wait);
if (!renewed) {
    throw new IllegalStateException("Lease lost; stop work where possible");
}
TaskSnapshot current = queue.find(lease.id()).block(wait);
System.out.println(current.expiresAt());
```

Для действующей аренды срок будет не раньше, чем время базы плюс 60 секунд. Меньшая запрошенная длительность не сокращает существующий срок. Просроченную аренду оживить нельзя.

- TaskLease — неизменяемый снимок момента захвата. Heartbeat не обновляет его expiresAt; актуальный снимок базы возвращает find.
- False от heartbeat означает, что продлить владение не удалось. Остановите работу, которую ещё можно отменить; отмена не отзовёт запрос, уже принятый внешней системой.
- Срок аренды задаётся целыми миллисекундами от 1 миллисекунды до 365 дней. Выбирайте его с учётом обработки, GC и сетевых пауз; универсального безопасного значения нет.

## 6. Повторять, ограничивать попытки и возвращать просроченные задачи

Fail явно освобождает действующую аренду. Восстановление обрабатывает работников, которые исчезли, не освободив её.

```java
boolean released = queue.fail(lease, Duration.ofSeconds(5),
    "Temporary upstream timeout").block(wait);
TaskSnapshot current = queue.find(lease.id()).block(wait);
System.out.println(released + ", " + current.state());
```

Если попытки остались: true, READY, с доступностью через 5 секунд. На последней разрешённой попытке: true, DEAD. Старый lease возвращает false.

```java
int recovered = queue.recoverExpired("mail", 100,
    Duration.ofSeconds(5)).block(wait);
System.out.println(recovered);
```

Результат: от 0 до 100 обработанных просроченных аренд. Задачи с оставшимися попытками становятся READY с задержкой; задачи с исчерпанным лимитом — DEAD.

- Попытка учитывается при захвате, а не на первой строке обработчика. Падение до начала обработки тоже расходует попытку.
- Новый захват увеличивает поколение и выдаёт свежий токен. Старый работник не может завершить или отклонить новую аренду.
- Восстановление ограничено размером партии и допускает вызовы из нескольких процессов. Запускать его должно приложение: наступление срока само по себе не выполняет SQL восстановления.
- Строки DEAD и DONE остаются для диагностики и политики хранения. Автоматического повтора из DEAD, планировщика архивации или скрытого бесконечного цикла повторов нет.

> **Не записывайте секреты в диагностику**
>
> Строка ошибки сохраняется без изменений и ограничена 2048 символами. Уберите секреты и лишние персональные данные до вызова fail.

## 7. Управлять жизненным циклом и пулом соединений

Библиотека согласует строки задач. Приложение определяет, когда опрашивать очередь, запускать обработчики, продлевать аренду и восстанавливать оставленную работу.

```java
Mono<Integer> oneRecoveryPass = queue.recoverExpired("mail", 100, Duration.ZERO);
int changed = oneRecoveryPass.block(wait);
System.out.println("Recovered in this pass: " + changed);
```

Конечный проход выполняет одну операцию восстановления и возвращает управление. Повторение, паузы и остановку явно определяет приложение.

- Каждая подписанная операция получает одно auto-commit соединение и освобождает его при завершении, ошибке или отмене. В PgTaskQueue можно передать ConnectionFactory из пула, которым владеет приложение.
- Не передавайте фабрику соединений, привязанную к текущей транзакции. Транзакция не остаётся открытой во время обработчика; submit не атомарен с произвольными записями приложения.
- Если изменение домена и отправка задачи должны фиксироваться вместе, используйте outbox или другую явно спроектированную транзакционную схему.
- Ограничивайте параллельную обработку с учётом пула базы и внешних сервисов. Виртуальные потоки в новых JDK не увеличивают число соединений PostgreSQL.
- Отмена или потерянный ответ могут оставить зафиксированную аренду без пригодного результата у вызывающего кода. Дождитесь истечения и восстановления; не придумывайте замену токену.

## 8. Запустить пример и разобрать ошибки

Скачиваемый пример — конечный сценарий с проверками. Он сохраняет созданные строки, не удаляет таблицы и не изменяет схему вашего приложения.

Скачайте вместе Example.java, pom.xml и schema.sql. Нужны Java 17+, Maven 3.8+ и установленный локально pg-task-lease 0.3.0. База ниже временная и слушает только localhost. Её учётные данные предназначены исключительно для примера.

```bash
docker run --rm -d --name pg-lease-docs \
  -e POSTGRES_DB=pg_task_lease_demo -e POSTGRES_USER=lease_demo \
  -e POSTGRES_PASSWORD=lease_demo_only -p 127.0.0.1:55433:5432 postgres:17-alpine
until docker exec pg-lease-docs pg_isready -U lease_demo -d pg_task_lease_demo; do sleep 1; done
docker exec -i pg-lease-docs psql -U lease_demo -d pg_task_lease_demo \
  -v ON_ERROR_STOP=1 < schema.sql
export TASKS_R2DBC_URL='r2dbc:postgresql://lease_demo:lease_demo_only@localhost:55433/pg_task_lease_demo'
mvn -q compile dependency:build-classpath -Dmdep.outputFile=target/classpath.txt
java -cp "target/classes:$(cat target/classpath.txt)" Example
docker stop pg-lease-docs
```

Запускайте из каталога скачанного примера. Останавливайте только созданный вами контейнер; последняя команда удалит этот демонстрационный контейнер с флагом --rm.

```text
submit: inserted=true, duplicate=false
claim: 2 workers, 2 distinct tasks
heartbeat: true; complete: true, then false; state=DONE
retry: attempt=2, new token; stale complete=false; state=DEAD
recovery: 1 expired lease requeued; attempt=2; state=DONE
finished: 2 DONE, 1 DEAD; no ready tasks
```

Ожидаемый вывод. Пример проверяет переходы очереди, а не реальную отправку письма, платёж или exactly-once доставку.

- Зависимость не найдена: версия 0.3.0 не опубликована в Central. Установите соответствующую рабочую копию через publishToMavenLocal и повторите разрешение зависимостей приложения.
- relation "public.pg_task_lease" does not exist: примените schema.sql к той же базе, которая указана в TASKS_R2DBC_URL. Не удаляйте существующую рабочую таблицу ради исправления ошибки миграции.
- Пустой захват: проверьте имя очереди, состояние READY, задержку availableAt, лимит попыток и конкурентные блокировки. Пустой список — нормальный результат, а не ошибка соединения.
- complete, fail или heartbeat возвращает false: аренда старая, просроченная, уже освобождённая либо задача завершена. Проверьте find(id); не обходите проверку владения.
- ConnectionFactory must supply auto-commit connections: используйте отдельную auto-commit фабрику или пул, а не соединение текущей транзакции приложения.

> **Тестовый набор библиотеки**
>
> Набор тестов библиотеки проверен на Java 17/21/25/27 с настоящим PostgreSQL. Он включает 12 работников на 96 задач, проверку старых токенов и истечение аренды во время ожидания блокировки. Запускайте тесты только на временной базе с именем, заканчивающимся на _test: набор пересоздаёт свою таблицу. Скачиваемый Example.java таблицы не пересоздаёт.
